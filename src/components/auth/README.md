# Сессия и запуск приложения

## Overview

Компоненты дают интерфейсу состояние текущего аккаунта и управляют экраном запуска приложения.

## Interface

- `SessionProfile` описывает данные профиля. `AccessProvider` и `useAccess` предоставляют идентификатор пользователя, профиль, роль, разрешение на публикацию, статус загрузки и операции обновления профиля. [access-provider.tsx](./access-provider.tsx)
- `AppStartup` оборачивает содержимое экраном запуска. `useRouteWarmup` возвращает функцию предварительной загрузки маршрута. [app-startup.tsx](./app-startup.tsx)

## Invariants

- `AccessProvider` меняет идентификатор в ресурсе сессии сразу при событии авторизации. Роль берётся только из профиля с завершённым онбордингом. `canPublish` вычисляется как наличие прав администратора или роли учителя. Сервер проверяет доступ к операциям самостоятельно. [access-provider.tsx](./access-provider.tsx)
- `AppStartup` блокирует интерфейс на маршрутах приложения во время ожидания сессии или при ошибке загрузки без профиля. Фоновая предварительная загрузка требует готового профиля с завершённым онбордингом и пропускается при экономии трафика или соединении 2G. [app-startup.tsx](./app-startup.tsx)

## Side Effects

- `AccessProvider` читает `profiles`, вызывает `is_instruction_admin`, подписывается на изменения сессии и обновляет данные при возвращении на вкладку. [access-provider.tsx](./access-provider.tsx)
- `AppStartup` вызывает `router.prefetch` с паузами. Повторная попытка обновляет профиль для известного аккаунта или перезагружает страницу. [app-startup.tsx](./app-startup.tsx)

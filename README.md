# Brick Studio

Brick Studio — платформа для обучения робототехнике на реальных наборах. Самоучка может собрать и запрограммировать своего робота, преподаватель — провести занятие по собственной программе, а родитель — увидеть проект и навыки ребёнка.

Первый рынок — кружки и частные школы робототехники в Казахстане, у которых уже есть LEGO SPIKE Prime или MINDSTORMS EV3. Начинаем с одного полного сценария: преподаватель назначает урок со стартовым проектом, ученик собирает робота, проверяет программу и сдаёт работу, а преподаватель подтверждает освоенный навык. После проверки результат становится доступен привязанному родителю.

## Направление продукта

**Умные роботы на знакомых наборах.** Планируем добавить уроки с ИИ и компьютерным зрением, где смартфон служит камерой, а программа робота на Pybricks реагирует на результат распознавания. Первый прототип — сортировщик: телефон распознаёт предмет, а робот SPIKE направляет его в нужный лоток. Ученик сможет проверить, как освещение влияет на распознавание, и доработать программу.

**Меньше ручного ввода для кружка.** Работы и подтверждённые навыки должны сохраняться по ходу занятия. Менеджер сможет собрать сводку по группе из этих данных, а привязанный родитель — увидеть результат своего ребёнка. В пилоте сравним этот процесс с тем, как кружки сейчас ведут Excel, CRM и переписку с родителями.

## Что работает сегодня

- Рабочий стол с настройками оформления. Проекты можно создавать, открывать, переименовывать, удалять, импортировать и экспортировать.
- Блочный редактор проектов для SPIKE Prime и EV3. В редакторе есть листы, пробная проверка программы и экспорт Python для Pybricks. Прямое Bluetooth-подключение из редактора предусмотрено для SPIKE Prime. [Проверка на хабе](./specs/004-controller-block-program/quickstart.md)
- Каталог опубликованных инструкций по сборке и QR-привязка родителя к аккаунту ученика. [Документация веб-приложения](./src/app/README.md)

## План развития

1. **Организации и доступ.** Ввести школы, роли, группы и серверную проверку лимитов тарифа. Личный аккаунт сможет работать и самостоятельно, и в составе школы. Перед внешним пилотом проверим размещение ученических данных и доступ к ним.
2. **Первый платный пилот.** Провести полный цикл урока на своей группе, затем дать 2–3 независимым кружкам Астаны провести четыре занятия. Проверим, может ли преподаватель сам назначить следующий урок, сколько времени уходит на поддержку и кто продлевает подписку.
3. **Прототип урока с компьютерным зрением.** Проверить на реальном SPIKE связку камеры смартфона, модели распознавания и программы на Pybricks. Затем проверить, может ли преподаватель самостоятельно провести урок.
4. **Инструменты для школ.** Развивать библиотеку уроков, роли и отчёты Pro по результатам пилота. Уроки смогут иметь варианты для разных наборов. Персонажей и острова будем связывать с освоенными навыками и завершёнными проектами.

## Локальный запуск

```sh
npm run dev
```

Откройте `http://localhost:3000/`. Для запуска собранной версии выполните `npm run build`, затем `npm start` и откройте `http://localhost:8080/`. Для проверок используйте `npm test`, `npm run test:hub` и `npm run test:full`.

## Техническая справка

### Конфигурация

- [`next.config.mjs`](./next.config.mjs) перенаправляет прежний маршрут `/controller.html` и сохраняет старые адреса входа, аватара и редактора.
- [`capacitor.config.ts`](./capacitor.config.ts) задаёт адрес Android-оболочки. Переопределение `TLC_ANDROID_SERVER_URL` принимает HTTPS без учётных данных в URL.
- [`postcss.config.mjs`](./postcss.config.mjs) подключает Tailwind и Autoprefixer. [`tailwind.config.ts`](./tailwind.config.ts) задаёт источники классов и переменные темы.

### Структура репозитория

- [Веб-приложение](./src/README.md) содержит маршруты Next.js, компоненты и вспомогательные модули.
- [Публичные ресурсы](./public/README.md) содержат браузерные скрипты и программы для Pybricks.
- [Supabase](./supabase/README.md) содержит базовую схему и миграции для профилей, каталога, наград и рабочего стола.
- [Android](./android/README.md) собирает оболочку Capacitor.
- [Диагностика](./diagnostics/README.md) содержит отдельную Bluetooth-проверку для SPIKE.
- [Скрипты обслуживания](./scripts/README.md) обновляют PDF worker и настраивают загрузку в Drive.

### Формат и хранение данных

- [`PROJECT_VERSION` и `HUBS`](./src/lib/projects.ts) задают формат проекта и типы наборов для рабочего стола и редактора.
- [`account_workspace`](./supabase/migrations/20261110160000_account_workspace.sql) хранит секции рабочего стола по аккаунту. Запись через `save_workspace_section()` сверяет ревизию.

### Сохранение и работа с хабом

- Рабочий стол и редактор сохраняют проекты в браузере через [`saveEditorProjects()`](./src/lib/projects.ts). Настройки рабочего стола могут синхронизироваться с базой через `save_workspace_section()`.
- Редактор может подключаться к хабу и отправлять команды для проверки программы. Сценарии и ограничения описаны в [быстрой проверке редактора](./specs/004-controller-block-program/quickstart.md).

### Проверки

- `npm test` запускает проверки JavaScript и симуляцию контроллера на Python.
- `npm run build` собирает веб-приложение. Проверки на физическом хабе описаны отдельно в [быстрой проверке редактора](./specs/004-controller-block-program/quickstart.md).

### Проекты

Версия формата файла — `1`, расширение экспорта — `.robotproj.json`. Структура: `version`, `id`, `name`, `hub` (`spike` или `ev3`), `createdAt`, `updatedAt`, `devices`, `workspace`. Импорт создаёт копию с новым идентификатором.

### Блок движения

Добавьте «Движение мотора» на доску, выберите порт, направление, значение и единицу: обороты мотора, градусы мотора или секунды. Обороты относятся к валу мотора без учёта передачи. Направление вращения зависит от установки мотора. Через «Программа Pybricks» можно скачать `.py`, загрузить его в Pybricks Code и запустить на хабе.

### Связанные моторы

Блок «Связанные моторы» задаёт два разных моторных порта и отдельное направление каждого мотора. Общие модули «Скорость» (°/с), «Мощность» (%) и «Величина движения» присоединяются справа. Скорость и мощность — альтернативные режимы. Мощность доступна только с секундами. Для запуска нужен модуль величины движения.

Моторы запускаются друг за другом без ожидания завершения первого, затем программа ожидает завершения обоих. Время общее, обороты/градусы задаются для каждого вала. При совместном запуске прямолинейность зависит от сборки и направлений моторов. Коррекция курса через DriveBase отсутствует. При ошибке во время действия программа пытается затормозить оба мотора. На EV3 используется API Pybricks 2 (`control.done`), на SPIKE — `done`. Новые блоки поддерживают сохранение и экспорт проекта.

### Цепочки и листы

Поднесите верх блока к низу другого (в пределах 36 единиц доски), чтобы подсветить цель, после отпускания блок прикрепляется. Перемещение верхнего блока переносит всю цепочку ниже. Перетаскивание среднего отделяет нижнюю часть цепочки; кнопка ↗ явно отсоединяет её. Можно вставить цепочку между связанными блоками. При удалении среднего блока соседние соединяются. Номера показывают шаги внутри цепочки.

Каждая цепочка выполняется сверху вниз. Порядок цепочек определяется положением верхнего блока сверху вниз, а при равной высоте — слева направо. Пустые блоки пропускаются. Порядок добавления параметров мотора на выполнение не влияет.

Вкладки листов находятся внизу, как в таблицах: + создаёт лист, ✎ переименовывает, × удаляет после подтверждения. Последний лист удалить нельзя. У каждого листа свои блоки, цепочки и положение доски. Проекты старого формата открываются на листе «Основная». Импорт/экспорт проекта сохраняет все листы; экспорт Python берёт только активный лист. Листы пока служат именованными пространствами для организации программы. Вызовы листов, параметры методов, классы и экземпляры ещё предстоит реализовать.

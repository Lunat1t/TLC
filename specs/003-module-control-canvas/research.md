# Исследование: поле управления модулями

## Решение 1 — левая панель и отдельный выбор модуля

**Decision:** использовать в пульте левую панель с карточками модулей, «+» и общей галочкой; «+» открывает отдельное окно выбора, которое закрывается после выбора.

**Rationale:** редактор блоков уже применяет левую палитру, мобильный выдвижной вариант и тактильный LEGO стиль (`src/app/editor/page.tsx`, область палитры и мобильного оверлея). Ученик видит поле во время настройки. Сейчас пульт открывает центральный `dialog`, который закрывает поле (`public/controller.html`, `public/controller.js`).

**Alternatives considered:** оставить центральный диалог с вложенным меню — поле не видно при добавлении; размещать «+» поверх поля — смешивает создание модуля с управлением роботом.

## Решение 2 — отдельные блоки для каждого модуля

**Decision:** каждый `device.id` получает один блок управления. Привод использует крестовину, одиночный мотор и группа — две стрелки и собственный замок вращения. Один привод сохраняет ограничение текущей модели.

**Rationale:** текущие `devices` уже описывают привод на 2/4 мотора, мотор и группу из двух моторов; порт не может принадлежать двум модулям (`public/controller-model.js`, `src/lib/controller-layout.ts`). Старый `gamepad.actionDeviceId` выбирает только один механизм и поэтому не подходит для нескольких независимых блоков.

**Alternatives considered:** оставить один общий блок «Действие» и переключать его на модуль — выбор модуля не даёт сразу его собственное управление; копировать старые элементы `controls` — они относятся к прежней сетке кнопок и не сохраняют связь 1:1 с устройством.

## Решение 3 — координаты, граница и мобильный экран

**Decision:** сохранять координаты блоков относительно доступной области поля в диапазоне 0…1. При рендере учитывать размер блока, ограничивать позицию внутри поля и разрешать высоте поля расти, если все блоки не помещаются. Новому блоку назначать первое свободное место. На узком экране выполнять детерминированную адаптацию без горизонтальной прокрутки и сохранять исходные координаты до подтверждённого перемещения.

**Rationale:** редактор блоков хранит положение и двигает блоки через pointer events и клавиатуру (`src/app/editor/page.tsx`), но его полотно бесконечно, поэтому нельзя копировать логику без ограничителя. Нормированные координаты переживают смену размера экрана лучше пикселей.

**Alternatives considered:** пиксельные координаты — на телефоне блоки могут оказаться за границей; жёсткая сетка — не даёт ученику свободно расположить управление; горизонтальная прокрутка — скрывает органы управления на телефоне.

## Решение 4 — подтверждение и безопасный режим управления

**Decision:** держать изменения в черновике до галочки. Вход в режим размещения вызывает остановку всех моторов и сброс всех замков. Во время размещения блоки перемещаются, но не посылают моторные команды. Галочка валидирует весь черновик, сохраняет его и закрывает панель; закрытие без галочки возвращает подтверждённую раскладку.

**Rationale:** текущий редактор модулей уже использует `draft` и сохраняет по «Готово» (`public/controller.js`). Существующие `releaseAll`, READY gate и таймаут программы хаба 600 мс обеспечивают остановку при потере связи (`public/controller.js`, `public/hub_program.py`). Отдельный замок каждого мотора относится к вращению, а не к размещению.

**Alternatives considered:** сохранять после каждого жеста — случайное касание портит раскладку и вызывает лишние облачные записи; разрешать управление при редактировании — жест перемещения может запустить мотор.

## Решение 5 — сохранение и миграция

**Decision:** расширить текущую конфигурацию версии 1 полем `moduleLayout` с позицией для каждого `device.id`. Оба валидатора нормализуют старую конфигурацию без поля, сохраняют существующие устройства и настройки портов и возвращают один канонический результат. Готовую раскладку отправлять в существующий `GET/PUT /api/controller-layout`.

**Rationale:** локальная копия хранится под `tlc.controller-layout.v1`, а сервер сохраняет только поля, возвращённые собственным валидатором. Новое поле, добавленное лишь в браузере, было бы потеряно после облачного сохранения (`public/controller-model.js`, `src/lib/controller-layout.ts`, `src/app/api/controller-layout/route.ts`).

**Alternatives considered:** отдельный API для координат — дополнительные гонки между модулями и размещением; повышать версию всей схемы без необходимости — сложнее восстановить уже сохранённые конфигурации.

## Уточнённые границы

- В окне выбора показывать только моторные типы, поддерживаемые нынешней программой Pybricks. Датчики требуют новых команд и отдельного плана.
- Использовать имеющееся ограничение до 12 модулей и один привод; на телефоне поле растёт по высоте.
- Сохранять скорость и реверс каждого порта в левой панели настроек, не возвращая нижние панели «Скорость» и «Помощь» на поле.

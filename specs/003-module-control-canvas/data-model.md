# Модель данных поля управления

## Сохранённая конфигурация

`ControllerConfig` остаётся конфигурацией версии 1. Существующие поля `hub`, `ports`, `devices`, `gamepad` и `controls` сохраняются для совместимости; `moduleLayout` добавляет расположение управления. Клиентский `validateConfig` и серверный `validateControllerConfig` должны возвращать одинаковую каноническую схему.

### Device

Существующий модуль с устойчивым `id`, `name` и одним из типов:

| Тип | Порты | Блок управления |
| --- | --- | --- |
| `drivetrain` | `leftPorts` и `rightPorts` по 1 или 2 порта | четыре стрелки: ход и поворот |
| `motor` | один `ports` | вперёд, назад, замок вращения |
| `motor-group` | два `ports` | вперёд, назад, замок вращения для обоих портов |

Ограничения уже действуют: до 12 устройств, один привод, порт принадлежит максимум одному устройству и существует на выбранном хабе. При смене хаба недопустимые назначения исправляются в черновике до подтверждения.

### ModulePlacement

Новый элемент массива `moduleLayout`:

| Поле | Тип | Правило |
| --- | --- | --- |
| `deviceId` | string | совпадает ровно с одним `devices[].id`; уникален |
| `x` | finite number | от 0 до 1 включительно |
| `y` | finite number | от 0 до 1 включительно |

`x` и `y` задают долю свободного хода верхнего левого угла блока: доступная ширина/высота поля минус размеры блока. На каждом размере экрана видимые пиксельные координаты ограничиваются реальным прямоугольником поля. Если несколько блоков после сжатия сталкиваются, отображение разводит их в порядке `devices`, при необходимости увеличивая высоту поля; сохранённые координаты меняются лишь после подтверждённого перемещения. Число элементов равно числу устройств. Элемент без модуля или два элемента для одного модуля недопустимы.

**Миграция:** если `moduleLayout` отсутствует в старой конфигурации, позиции назначаются детерминированно в порядке `devices`. Устройства, порты, скорость, реверс и направление сохраняются. Если конфигурация содержит корректные позиции для части устройств, недостающие позиции создаются; лишние позиции от удалённых устройств убираются при нормализации. Некорректные числовые значения отклоняются, чтобы сервер не принял недостоверную раскладку.

## Несохранённое состояние страницы

| Состояние | Значение | Назначение |
| --- | --- | --- |
| `mode` | `operating` или `editing` | отделяет работу моторов от размещения |
| `draft` | копия `ControllerConfig` | все изменения до галочки |
| `pickerOpen` | boolean | отдельный выбор модуля |
| `drag` | `deviceId`, pointer ID, начальные координаты | временный жест; не сохраняется до `pointerup` |
| `pressedByDevice` | map `deviceId → направления` | живые команды только в `operating` |
| `lockedMotorIds` | set `deviceId` | непрерывное вращение отдельных моторных блоков |

`mode` и замки не записываются в профиль. После загрузки, перезагрузки и восстановления вкладки режим — `operating`, все моторные вводы отпущены и замки сброшены. `editing` допускается без Bluetooth. Вход в него вызывает `releaseAll`; закрытие без галочки уничтожает `draft`.

## Переходы

```text
operating --Настроить/Стоп--> editing
editing --+/выбор--> editing + новый Device + ModulePlacement
editing --перемещение--> editing + координаты только в draft
editing --Готово ✓/валидация/сохранение--> operating
editing --Закрыть или Escape--> operating с прежней конфигурацией
operating --потеря READY/Стоп/скрытие вкладки--> operating + все команды = 0
```

Удаление устройства в черновике удаляет его `ModulePlacement` и сбрасывает связанные моторные вводы. Подтверждение проходит только когда все модули имеют допустимые порты и размещение.

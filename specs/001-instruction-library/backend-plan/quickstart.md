# Проверка бэкенда TLC

Подготовить отдельные тестовые Supabase и папку Drive, разрешённый PDF, администратора и тестовые аккаунты. Проверить историю миграций и зависимости согласно `supabase/migrations/README.md`; настроить серверные переменные по `docs/instruction-library-setup.md`, не передавая ключи в чат или Git.

1. `npm install`, `npx tsc --noEmit`, `npm test`, `npm run build`; затем `npm run dev`. Главная, её CSS и JS возвращают 200, dev/build не перезаписывают общий кэш одновременно.
2. Проверить фактический проект и Data API до и после миграций: каталог возвращает 200 и тестовые карточки; Drive file ID виден только у опубликованных инструкций.
3. Проверить вход, обновление истекшей сессии, выход, отказ роли и недоступность базы; cookies обновляются, ошибки различимы.
4. Преподаватель загружает PDF через форму в папку Drive; Supabase хранит черновик и file ID. TLC включает `anyone:reader`. Проверить дубликат/повтор, права service account, запрет публичного доступа политикой Google Workspace, размер и недоступность Drive.
5. Проверить, что нажатие опубликованной карточки получает redirect к Google's `webContentLink` и начинает скачивание без Google-входа и PDF-просмотрщика TLC.
6. После реализации занятий проверить адресный запуск изображений шагов, повторный запрос, замену планшета, потерю сети и восстановление прогресса.
7. Проверить скачивание PDF в браузерах планшета и телефона; PDF передаётся Google Drive напрямую, Range и прогресс не обслуживаются TLC.
8. Проверить PDF на границе 100 000 000 и 100 000 001 байт: первый допускается, второй отклоняется с сохранением черновика. Проверить, что содержимое PDF не проходит через Vercel.
9. На главном экране открыть библиотеку кнопкой и свайпом; проверить клавиатуру, доступные подписи и отсутствие случайного переключения при прокрутке.

Ссылку на Drive можно копировать и отправлять отдельно от TLC. После снятия карточки с публикации прямая ссылка продолжает работать, пока администратор не отзовёт `anyone:reader` permission в Google Drive.

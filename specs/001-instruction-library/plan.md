# План реализации: бэкенд библиотеки TLC

**Ветка:** `001-instruction-library` | **Дата:** 2026-11-04 | **Спецификация:** [spec.md](spec.md)

## Цель и технический контекст

Восстановить каталог Supabase, исправить серверную авторизацию, подключить PDF из Google Drive и реализовать безопасную выдачу ученикам. PDF остаются в Drive; Supabase хранит метаданные, права и состояние занятий. Next.js 15, React 19, TypeScript, Supabase Auth/Postgres/RLS, Drive API; Storage используется для изображений. На первом этапе проверять одного преподавателя и четырёх учеников; PDF до 100 МБ (100 000 000 байт) включительно, измерения производительности проводить на тестовом оборудовании. Синхронизация проектов редактора — отдельный вопрос.

## Constitution Check

`.specify/memory/constitution.md` — незаполненный шаблон; формальную конституцию проверить невозможно, не считать её утверждённой. Проверены требования спецификации: роли, текущий планшет и неизменяемая версия открытого занятия. **Открытый gate:** сохранение доступной неизменяемой версии PDF в Drive необходимо доказать на тестовом аккаунте до реализации выдачи как готовой функции; `modifiedTime` этого не гарантирует. Повторная проверка после проектирования даёт тот же результат.

## Этапы

1. Идентифицировать тестовый проект Supabase, проверить миграции, таблицы, grants/RLS и schema cache; ранее наблюдались PGRST202/PGRST205, но причина не подтверждена. Применить недостающие миграции на тестовом проекте по `supabase/migrations/README.md` и восстановить API каталога.
2. Исправить ожидание обновления cookies middleware, убрать неявный fallback к другому проекту и различать ошибку зависимости и запрет роли. Проверить вход, выход и продление сессии.
3. Подготовить главный экран с нижней навигацией и свайпом к библиотеке; предусмотреть клавиатуру и сохранение работы редактора. Уровень и косметика аватара остаются будущими функциями. Настроить сервисный аккаунт Drive и тестовую папку; закрытая форма потоково загружает PDF в папку, после чего сохраняет в Supabase Drive ID и закреплённую revision ID. Сама страница может быть открыта без входа, но серверная запись требует проверенную роль редактора. Проверить права, валидацию, 403/404/429 и лимиты. Добавить управляемую публикацию с подтверждением прав.
4. Проверить закреплённую версию Drive с необходимыми правами и retention до завершения активных запусков; при невозможности восстановить версию блокировать запуск. Возможная альтернатива — неизменяемые отдельные PDF в Drive, после проверки управления доступом и резервного копирования. Supabase Storage для копий PDF не использовать.
5. Реализовать текущий планшет с fencing, выбор, атомарный адресный запуск и snapshot, постраничный PDF с Range и сохранением страницы, восстановление после потери связи, прогресс и смену планшета. Прямой Data API не должен обходить проверку активного планшета.
6. Подготовить разные окружения и безопасный порядок dev/build, проверку HTML/CSS/JS, журналы без секретов, мониторинг, резервные копии и сценарии восстановления.

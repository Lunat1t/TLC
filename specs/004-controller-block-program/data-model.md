# Data model: область управления и программа

## Workspace и геометрия

Внешний `RobotProject.version` остаётся 1. Проект содержит прежние sheets/activeSheetId и новое поле `workspace.controlLayout`:

```text
ControlLayout {
  version: 1
  areas: ControlArea[]
  controls: ControlInstance[]
  migration?: { source: "legacy-button-events"; version: 1 }
}
ControlArea { id; sheetId; title; x; y; width; height }
ControlInstance {
  id; areaId
  kind: "drivetrain" | "joystick" | "dpad" | "motor" | "motor-group" | "legacy-buttons"
  label; x; y; width; height
  keyBindings?: Record<input, physicalKeyCode>
}
```

- Область визуально представлена большим блоком «Управление», но не является `WorkspaceBlock` с `parentId`. Начальная область 640×360 логических единиц; минимум 320×240. Максимальный размер 2400×2400; заголовок 44. Размеры — ограниченное проектное решение первой версии.
- x/y области находятся в системе координат листа; координаты элементов — в локальной системе содержимого области без заголовка. Значения конечные; координаты детей неотрицательны, весь bounding box внутри содержимого. ID уникальны в проекте, `sheetId/areaId` должны существовать.
- Лимиты: 12 областей на проект, 12 controls на область. Названия от 1 до 40 символов. Программные блоки сохраняют текущие пределы 200 на лист и 32 листа.
- При уменьшении области её размер ограничивается bounding box детей; скрытого обрезания нет. При добавлении ищется свободное место; если его нет, предлагается увеличить область. Пересечения после ручного перемещения не подтверждаются, элемент возвращается в последнее допустимое положение.
- Drivetrain минимум 160×160, joystick и dpad минимум 176×176, motor/group 144×96; legacy-buttons 300×200. Joystick использует круговую рабочую зону и возвращает ручку в центр при отпускании. Размер крестовины и остальных кнопок после отображения не меньше 44×44 CSS px независимо от zoom; режим проверки отображает управление в читаемом масштабе и допускает вертикальную прокрутку.
- В control нет моторных портов, скорости, реверса или автозапуска. motor и motor-group различаются представлением и названием, но действия всегда задаются программой ученика.

## Inputs и события

| kind | Стабильные input ID |
| --- | --- |
| drivetrain | up, down, left, right |
| joystick / dpad | up, down, left, right |
| motor / motor-group | forward, backward |
| legacy-buttons | up, down, left, right, a, b, x, y, l, r |

```text
ButtonBlock extends WorkspaceBlock {
  type: "button"
  target: { controlId: string; input: string }
  event: "pressed" | "released"
}
```

Метки вычисляются из control.label и input. Переименование, перенос и resize не изменяют target. В одном проекте не более одного обработчика `(controlId,input,event)`, включая разные листы. Шапки остаются корнями; вложенные start/button/if в обработчиках кнопок запрещены. Пустой обработчик даёт предупреждение, не создаёт действий. События могут ссылаться на элементы другого листа, но проверить их кнопки можно только когда их область видима; смена листа останавливает сессию.

При удалении элемента/области/листа обработчики не удаляются автоматически, а получают `missing-control`. При замене kind несовместимые input сохраняются с `invalid-input` до исправления учеником. Копирование области создаёт новые ID элементов; существующие обработчики по умолчанию остаются с оригиналом. При клонировании листа копируются его обработчики и области с remap внутренних целей; внешние ссылки остаются прежними, дубли обработчиков диагностируются. Копия всего проекта сохраняет внутренние ID в новом изолированном проекте.

## Действия и результат компиляции

`drive/pair/stop` и `MotorModule = speed | power | travel` сохраняют текущую модель. Модуль скорости хранится в моторном блоке; без модуля применяется текущая константа 360°/с. Speed и power взаимоисключающие; travel+power допустим только в секундах; порты pair различны и допустимы для хаба.

```text
CompiledProgram {
  projectId; revision; hub; protocol: 2 | 3
  startup: Action[]
  handlers: { target; event; sourceBlockId; actions: Action[] }[]
  diagnostics: { scope: "global" | "startup" | "handler";
                 severity: "error" | "warning"; blockId?; target?; code; message }[]
}
Action = run(port,speed) | dc(port,power) | angle(port,speed,degrees)
       | time(port,speed,ms) | dcTime(port,power,ms) | stop(port) | wait(ms)
```

Одна чистая функция компилирует допустимые моторные цепочки start и button, используя существующие действия. Один start на проект для встроенного исполнения; ноль — допустим. Его цепочка выполняется один раз при явном старте. Неподдерживаемые конструкции в startup дают ошибку до выполнения всей сессии. Глобальная ошибка также блокирует старт; ошибка конкретного handler блокирует только его. Пустой input даёт событие без команды. Ошибка обработчика нажатия или отпускания блокирует соответствующую экранную кнопку целиком, сразу показывает на ней значок и доступную подсказку; остальные исправные кнопки работают. У удалённой цели индикация остаётся на шапке события и в списке ошибок.

Live: без travel моторный блок вращается до явного stop/новой команды/общего стопа. С travel выполняется существующая ограниченная операция. Автономный экспорт сохраняет прежний обязательный travel и прежние ошибки, не включает layout или button-цепочки; блок под start с travel работает прежним образом.

Порты SPIKE A–F, EV3 A–D для редактирования/экспорта. Online/trial контроллер рассчитан на SPIKE, EV3 показывает `unsupported-hub` для live. Протокол v2 допускает только m/stop со скоростью до 600°/с; v3 поддерживает d/a/t и скорость до 1000. Ограничения wire сохраняются, превышения не отправляются на хаб.

## Состояние сессии

```text
viewMode: edit | check
programState: idle | trial-running | live-running | stopped
transportState: disconnected | connecting | connected | starting-hub | ready | fault
sessionEpoch: integer
snapshot: immutable CompiledProgram | null
runners: Map<chainKey, { abort; epoch }>
portOwners: Map<port, ownerToken>
heldInputs: Set<controlId/input>
log: LogEntry[<=30]
```

| Событие | Переход и эффект |
| --- | --- |
| Вход в check | idle; layout фиксируется; автостарт отсутствует |
| StartProgram без READY | trial-running; startup один раз; только журнал |
| Connect / StartHub / READY | меняется транспорт; trial автоматически не становится live |
| StartProgram после READY | отмена прошлой сессии, проверка, новый epoch, startup один раз, live-running |
| Нажатие/отпускание | выполнение только в running и по точному target; иначе нет команд |
| Stop/edit/project/sheet/blur/hidden/pagehide/dispose/fault | новый epoch, abort, очистка heldInputs и очереди; x при доступной связи; stopped |
| Разрыв связи | stopped/disconnected, watchdog тормозит хаб |

Очередь проверяет epoch/AbortSignal и владение портом перед записью. Непосредственно выполняющуюся BLE-запись отменить может быть невозможно; после её завершения стоп имеет приоритет, новые старые команды не запускаются. Один запрос stop в полёте: отменить epoch/очередь и heartbeat, отправить `x`, затем ожидать `SOCER2_STOP` до 1200 мс после успешной записи. До подтверждения старт запрещён. При таймауте/ошибке/разрыве — fault и отключение, UI сообщает об отсутствии подтверждения; возобновление только после нового подключения, READY и явного старта. Повторные stop объединяются, callbacks прежнего соединения игнорируются. Heartbeat не оставляет сессию исполняемой после ошибки/cleanup.

## Миграция и сохранение

1. До readSheets и включения autosave прочитать точный исходный JSON всего ключа проектов, проверить версии и построить миграцию в памяти. Неизвестная версия или повреждение — ошибка и сохранение исходных данных без перезаписи.
2. Старые button/event без target получают одну совместимую область и legacy-buttons control на листе первого события; ID детерминированы в namespace проекта. Все старые десять button ID переходят на этот control, действия/модули не меняются.
3. Старые автономные проекты без событий остаются без новой области. Уже мигрированный layout не меняется повторно. Некорректные/смешанные ссылки показываются, а не переназначаются молча.
4. До первой записи проверить созданный backup полного исходного ключа в localStorage. Под Web Lock перечитать и сравнить текущий исходник с первоначальным, после проверки атомарно заменить весь массив через один setItem; при конфликте, отсутствии безопасной блокировки, ошибке backup или записи запретить autosave, исходник не удалять, показать ошибку и предложить JSON-экспорт. После сбоя основной записи backup сохраняется. Сравнение без блокировки не даёт атомарного CAS; вкладки со старой версией приложения могут не соблюдать lock и не охвачены гарантией изоляции.
5. Explicit import старой `tlc.controller-layout.v1` переносит только совместимые типы/имена/геометрию в выбранный проект. Старые порты, процентные скорости и направления сохраняются в исходной резервной копии, не становятся программой.
6. `readSheets`, snapshot, экспорт/импорт проекта сохраняют layout и target; неизвестные поля workspace не отбрасываются без проверки версии. Работа с историческим layout API не требует изменения серверной схемы.

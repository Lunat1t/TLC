# Quickstart validation: единый редактор

Этот документ проверяет будущую реализацию. Вызов `speckit-plan` обновил только дизайн; описанное ниже ещё не объявляется работающим или испытанным.

## Подготовка

- Node.js с поддержкой текущего `--experimental-strip-types`, npm, Python 3; установленные зависимости проекта.
- Для интерфейса — браузер на компьютере и сенсорное устройство/эмуляция 360 px. Для реального управления — HTTPS либо localhost и браузер с Web Bluetooth, SPIKE Prime с текущей `public/hub_program.py`.
- Сохранить JSON-копии старого автономного проекта, проекта с десятью кнопками и старой глобальной раскладки. Для сравнения заранее получить экспорт автономного проекта на текущей версии.

Команды из корня проекта:

```bash
cd /home/bah/Documents/ChatGPT/Robots/socer-web
npm test
npx tsc --noEmit
npm run build
npm run dev -- --hostname 127.0.0.1
```

Зависимости уже присутствуют локально; при чистой копии выполнить `npm ci` перед проверками. В dev открыть `/`, создать/выбрать проект и перейти в `/editor?id=<id>`. Для производственной проверки после build запустить `npm start` (порт 8080).

## 1. Область, ввод и моторные модули

1. Добавить «Управление», перетащить Drivetrain и управление мотором внутрь. Переместить и изменить размеры области/элементов; переименовать их. Нельзя вывести элемент за границу, уменьшить область ниже содержимого или потерять его при масштабировании.
2. Перейти в проверку, запустить trial и нажать все кнопки. Без обработчиков журнал показывает вход, транспорт получает ноль моторных команд. В edit нажатия/drag/resize также не отправляют команды.
3. Добавить «Когда [Drivetrain 1 · ▲] нажата → Связанные моторы A/D», внутри блока — модуль скорости. В trial отпустить кнопку без обработчика отпускания: движение продолжается до иной команды или общего стопа. Затем добавить «Когда … отпущена → Стоп A/D» и проверить остановку при отпускании. Повторить для другого направления с написанными учеником действиями.
4. Этот же моторный блок с travel подключить к «Когда программа запускается». В trial startup выполняется один раз за старт, затем доступны события. Повторный рендер или READY не повторяет startup. Отдельного блока скорости в палитре нет.
5. Сохранить, перезагрузить, экспортировать JSON, импортировать копию проекта: область, target и модули сохранились.

Ожидание: единый экран; действие на пробное событие видно за 100 мс; все связи соответствуют [модели](data-model.md). Измерить через `performance.now()` от обработки pointerdown/keydown до первого `requestAnimationFrame`, в котором обновлён журнал; минимум 20 нажатий в обычном состоянии на проверяемом компьютере и планшете, записать модели устройств, браузер, разрешение таймера и максимальную задержку. Это измерение обновления кадра, а не доказательство физической задержки дисплея. Если максимум превышает 100 мс или устройство не проверено, SC-004 для него не считать пройденным.

## 2. Ссылки, ошибки и доступность

1. Создать два Drivetrain с одинаковой подписью и разными обработчиками: события адресуются разным ID. Переименование/resize не меняют реакцию.
2. До старта создать ошибку у одной кнопки: сразу видны значок и понятная подсказка, кнопка не исполняется; исправная соседняя кнопка работает. Исправить ошибку — значок исчезает. Удалить control: цепочка остаётся, шапка и список ошибок показывают missing-control; другое управление не наследует её.
3. Попробовать duplicate handler, неверный input, несколько start, неподдерживаемый блок в startup; видны scoped ошибки по [контракту](contracts/controller-program.md).
4. При 360 px доступны все controls, нет горизонтальной прокрутки страницы, кнопки ≥44 px. Перемещение за ручку, нажатие кнопки и вертикальный скролл не путаются.
5. Клавиатура работает в check, repeat не повторяет pressed; редактирование текста/параметров не запускает мотор. Pointer release вне кнопки приходит, pointercancel останавливает сессию.

## 3. Миграция и legacy URL

1. Открыть прежний проект с button enum: появляется совместимая область, каждый из 10 входов сохраняет исходные действия. Повторное открытие не создаёт дублей.
2. Открыть старый автономный проект: layout не навязывается, экспорт сравнить с сохранённым исходным байт-в-байт. Существующие ошибки экспорта также сохраняются.
3. Явно импортировать старую глобальную раскладку в один проект: вид/имена перенесены, программа автоматически не создана, процентная скорость не стала модулем °/с. Другие проекты не изменены.
4. Проверить ошибку записи backup/квоту storage и неизвестную будущую версию: исходник не потерян и не перезаписан.
5. `/controller.html?project=<id>` открывает `/editor?id=<id>`; неизвестный ID показывает сообщение и список проектов для явного выбора, URL без ID — список; автоматического выбора и запуска нет. Homepage, редактор и PWA shortcut не открывают отдельный пульт. Отдельные HTML/JS/CSS экрана удалены.

## 4. Автоматизированная проверка с fake transport/clock

Добавить существенные проверки к текущим `tests/controller-program.test.js`, `tests/workspace.test.js`, `tests/projects.test.js`, обновить `tests/controller-ui.test.js` и `tests/app.test.js`; зарегистрировать новые suites в `tests/run.js`.

- Roundtrip layout/target/module, идемпотентность миграции, remap клона листа и проекта, удалённая цель.
- Пустой control после READY выдаёт ноль команд; startup один раз за start; глобальные/start ошибки блокируют сессию, handler ошибка — только конкретную цель.
- Connect/READY без StartProgram не двигают моторы; trial не переключается в live автоматически.
- Общий stop, смена проекта/листа, edit и dispose abort-ят ожидания; команда старого epoch, уже стоящая в очереди, не отправляется. Ответ `SOCER2_STOP`, timeout 1200 мс после записи, застрявшая запись, разрыв, дубли и поздний ответ проверяются fake transport; heartbeat прекращается, ошибочная сессия закрывается, reconnect требует READY и явного старта.
- Отложенный stop старого владельца порта не останавливает новую команду другого обработчика; стартовая цепочка участвует в том же ownership.
- Strict Mode mount/cleanup не оставляет два heartbeat или notification listener; ошибка записи/ACK и LINK_LOST прекращают выполнение.
- Неизменность протокола и watchdog через существующий `tests/test_controller_hub.py`; v2 блокирует только неподдерживаемые действия, ошибки startup блокируют live-start.

Повторить npm test/typecheck/build и `git diff --check` после реализации. Эти проверки используют существующий harness; отдельный фреймворк не требуется.

## 5. Аппаратная приёмка

На безопасно установленном роботе загрузить программу хаба. Подключиться в редакторе, запустить хаб и убедиться, что READY сам по себе не запускает действия. Явно начать программу: проверить startup, написанные реакции нажатия/отпускания, реальные направления и параметры модулей. Пустой элемент не должен двигать моторы.

Проверить Stop, уход фокуса, hidden, разрыв Bluetooth, остановку программы хаба и возврат в edit; после каждого нужен явный новый старт. Отдельно записать время последнего принятого хабом пакета, команду brake и фактический покой; SC-004 требует физической остановки ≤600 мс от последнего пакета. Записать метод и разрешение измерения, число повторов и максимальное время. Текущий код проверяет условие `>600` в цикле с `wait(10)`, поэтому выполнение этого предела не доказано: превышение или отсутствие точного измерения означает, что SC-004 не пройден, и требует отдельного решения по критерию или программе хаба. Записать модель хаба, версию Pybricks/браузера, результат и непроверенные сценарии. Программная симуляция не заменяет эти измерения.

## Исходная проверка среды (до реализации)

Node.js v22.23.1, Python 3.14.8; зависимости установлены. Команды проверки находятся в `package.json` и `tests/run.js`. Программа `public/hub_program.py` использует SOCER3_READY, SOCER2_ACK, SOCER2_STOP и watchdog 600 мс с опросом примерно 10 мс; фактическая остановка не измерялась. Примеры и исходный экспорт сохранены в `tests/fixtures/controller/`.

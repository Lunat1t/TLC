# Research: единый редактор управления

**Date**: 2026-11-02 | **Scope**: корректировка 004. Источники — текущий локальный код; это исследование дизайна, а не отчёт об испытаниях будущей реализации.

## 1. Место области и координаты

**Decision**: область — визуальный блок с отдельной моделью в `workspace.controlLayout`; программные цепочки остаются в `sheets[].blocks`. Область имеет `sheetId`, элементы — `areaId` и локальные координаты. Перенос области не меняет детей.

**Rationale**: `src/lib/workspace.ts` связывает действия через `parentId` и whitelist в `readBlocks`; существующие жесты `src/app/editor/page.tsx` уже учитывают pan/zoom. Использование исполнительных связей для визуального контейнера нарушило бы обход цепочек. Обновить snapshot/readSheets вместе с моделью.

**Alternatives considered**: HTML-пульт во встроенном iframe сохраняет второй интерфейс и независимое состояние; помещение controls в моторную цепочку смешивает UI и программу.

## 2. Цель события и отсутствие встроенного поведения

**Decision**: адрес события `(controlId, input, event)`, имя — только подпись. Drivetrain выдаёт направления, motor/group — два направления; управление не содержит исполнительных портов или скорости. До написания обработчика ни одна кнопка не отправляет команду.

**Rationale**: `public/controller-program.js` сейчас использует глобальный enum десяти кнопок и ищет обработчик по button/event; это смешало бы два одинаковых элемента. `public/controller-model.js` содержит старые автоматические привязки к портам, непригодные для новой модели без явной программы.

**Alternatives considered**: ссылки на имя ломаются при переименовании; привязка по порту сохраняет скрытую моторную логику.

## 3. Моторные блоки и запуск

**Decision**: переиспользовать `drive/pair/stop` и `speed/power/travel`; не добавлять отдельную сущность скорости. Пробный и live исполнитель получают общий IR с `startup` и `handlers`. Автономный `generatePybricks` сохраняет действующие правила; область и события в экспорт не попадают.

**Rationale**: `src/lib/workspace.ts` и моторный renderer в `src/app/editor/page.tsx` уже поддерживают эти модули. Текущий `compileControllerProgram` обходит только button roots; потребуется явная компиляция start, а не предположение, что она уже есть. В автономном экспорте отсутствие travel даёт ошибку, и это поведение сохраняется.

**Alternatives considered**: копирование моторных блоков для управления создаёт два набора параметров. Выполнять Python экспорт в браузере не требуется. Онлайн-`if` в первой версии явно отклоняется; текущий автономный экспорт `if True` не используется как универсальная реализация условий.

## 4. BLE runtime и React

**Decision**: выделить headless сервис с `subscribe/connect/startHub/startProgram/dispatch/stop/disconnect/dispose`, обёрнутый React hook/component. `dispose` отменяет timers, runners, notifications, listeners и очередь записи. Сессия имеет epoch, задания — AbortSignal и ownership токены портов.

**Rationale**: `public/controller.js` использует module-level mutable state, поиск DOM по ID и глобальные обработчики. Он не пригоден для повторного монтирования React. `public/pybricks-protocol.js` и `public/notifications.js` можно сохранить. Код хаба уже содержит протокол v3 и `LINK_TIMEOUT_MS=600`; heartbeat клиента 150 мс, ACK timeout 1800 мс.

**Alternatives considered**: загрузка старого `<script>` в React дублирует listeners/таймеры; переписывание протокола увеличивает область риска без продуктовой необходимости.

## 5. Режимы проверки и конфликт портов

**Decision**: edit → checking-idle → trial-running или live-running. Connect и READY не запускают ученическую программу; требуется старт. Все изменения программы останавливают сессию. Новая команда передаёт владение портом; старые ожидания и finalizer не отправляют запоздалый стоп чужому владельцу.

**Rationale**: текущий runtime уже имеет `activeRunners` и `portOwners`. После объединения добавляется стартовая цепочка, поэтому владение нужно и между startup и событиями. Очередь BLE должна проверять актуальность до каждой отправки, включая команды, запланированные до stop.

**Alternatives considered**: запрет повторного порта в разных обработчиках запрещает нормальные противоположные направления; непрерывное выполнение во время drag приводит к случайным командам.

## 6. Совместимость сохранения

**Decision**: версия layout 1 внутри существующего workspace; старые проекты с button enum получают детерминированную область и `legacy-buttons` control со всеми десятью входами. Поля button мигрируют на target без переписывания действий. Нет обработчиков — нет автоматической области. Неизвестная будущая версия не перезаписывается.

**Rationale**: `src/lib/projects.ts` хранит workspace как объект и использует общий ключ `robot-studio-projects-v1`; менять внешний PROJECT_VERSION нет необходимости. Старая глобальная раскладка `tlc.controller-layout.v1` не привязана к проекту. Миграцию проверять повторным запуском и JSON roundtrip.

**Alternatives considered**: бесконтрольное присваивание глобальной раскладки каждому проекту создаёт ложные связи; потеря незнакомых полей при чтении необратима без резервной копии.

## 7. Полное удаление отдельного экрана

**Decision**: удалить `public/controller.html`, его DOM orchestrator и изолированный CSS после извлечения нужного кода. Через Next redirect направлять `/controller.html?project=...` на `/editor?id=...`; выбранный ID проверяется существующим хранилищем проекта. Обновить ссылки в редакторе, домашнем экране, manifest и README.

**Rationale**: текущие ссылки найдены в `src/app/editor/page.tsx`, `src/app/page.tsx` и `public/manifest.webmanifest`. `next.config.mjs` уже управляет legacy URL. Service worker `public/sw.js` работает network-only и не требует добавления кэша. Страница управления не сохраняется даже как скрытый второй UI.

**Alternatives considered**: оставить старый экран параллельно означает две несовместимые модели программы. Удалить URL без redirect ломает сохранённые ссылки учеников.

## 8. Подтверждение стопа и измерение

**Decision**: один `x` в полёте, после отправки ожидать именно `SOCER2_STOP` до 1200 мс; сбой — закрыть связь и требовать новое подключение, READY и явный старт. Отменить heartbeat и queued-команды до `x`, отбрасывать callbacks старой сессии. ACK не является подтверждением стопа.

**Rationale**: `public/hub_program.py` после `x` вызывает brake и отправляет `SOCER2_STOP`, а `SOCER2_ACK` периодический. Без ID запроса поздний ответ не позволяет безопасно различить две команды; сброс соединения после таймаута разделяет поколения. Watchdog проверяет интервал строго больше 600 мс и опрашивает цикл каждые 10 мс; физическое торможение не равно времени вызова brake. SC-004 остаётся неподтверждённым строгим критерием.

**Alternatives considered**: считать успешную BLE-запись или очередной ACK подтверждением — нельзя доказать обработку стопа; продолжать heartbeat после сбоя препятствует срабатыванию watchdog.

## 9. Миграция до первого сохранения и неизвестный проект

**Decision**: ещё до readSheets/autosave сформировать миграцию в памяти, проверить все данные, затем сохранить и перечитать точный backup полного ключа проектов; атомарно заменить запись только после проверки исходного значения и межвкладочной блокировки. При отсутствии безопасной блокировки не разрешать потенциально конкурентную запись. Неизвестный ID ведёт к выбору проектов с сообщением без автостарта.

**Rationale**: readBlocks и readSheets отбирают поля, snapshot заменяет workspace, а saveProjects перезаписывает общий массив. Сравнение без общей блокировки не является атомарным compare-and-swap; старые вкладки могут игнорировать новый lock, потому гарантировать их взаимную изоляцию нельзя. SC-007 прямо требует выбора проекта.

**Alternatives considered**: миграция после подключения autosave рискует утратой старых связей; бесшумный выбор первого проекта противоречит SC-007.

## Итог исследования

Неопределённости разрешены проектными решениями выше. Физические направления моторов, устройства и задержки не объявляются проверенными. Новые зависимости, схемы БД и внешние API не требуются. Исследование модели/жестов и транспорта/совместимости выполнено отдельными исследовательскими агентами согласно `speckit-plan`.

# Implementation Plan: Программа пульта из блоков

**Branch**: `004-controller-block-program` (контекст Spec Kit; текущая Git ветка `001-instruction-library`) | **Date**: 2026-11-01 | **Spec**: [spec.md](spec.md)

**Input**: убрать настройку со страницы пульта; программировать кнопки джойстика блоками в стиле VEXcode («когда кнопка нажата → действие»); проверять программу на странице пульта; сохранить стиль и UX/UI.

## Summary

Редактор получает категорию блоков «Пульт»: шапку «Когда кнопка [▲] [нажата|отпущена]» и блок «Стоп мотора»; под шапку ставятся существующие «Движение мотора» и «Связанные моторы». Страница пульта теряет панель «Настроить» и становится «исполнителем»: загружает проект из локального хранилища, компилирует обработчики общим ES-модулем, показывает 10 кнопок геймпада и ленту событий. Без хаба работает пробный режим; после READY действия отправляются хабу. Программа хаба расширяется до протокола v3 (точные обороты, секунды, мощность) с сохранением v2-команд, стопа и таймаута 600 мс.

## Technical Context

**Language/Version**: TypeScript 5.7 + React 19 (редактор), JavaScript ES modules (пульт), MicroPython/Pybricks (хаб)  
**Primary Dependencies**: Next.js 15, Tailwind 3, Web Bluetooth, существующие `pybricks-protocol.js`, `notifications.js`  
**Storage**: `localStorage["robot-studio-projects-v1"]` (проекты редактора); `tlc.controller-layout.v1` и `/api/controller-layout` больше не используются пультом, но не удаляются  
**Testing**: `npm test` (node test runner + `tests/test_controller_hub.py`), `npm run build`, браузерные сценарии и приёмка на хабе по [quickstart.md](quickstart.md)  
**Target Platform**: HTTPS браузер на компьютере и телефоне; SPIKE Prime / Robot Inventor с Pybricks  
**Project Type**: веб приложение (Next.js страницы + статическая страница пульта + программа хаба)  
**Performance Goals**: отклик ленты ≤ 100 мс; остановка при потере связи ≤ 600 мс; без сетевых запросов при нажатиях  
**Constraints**: команды моторам только в `live`; одна реализация правил компиляции; автономный экспорт Pybricks неизменен; стиль редактора/пульта сохранён; ширина 360 px без горизонтальной прокрутки  
**Scale/Scope**: 10 кнопок × 2 события ≤ 20 обработчиков, ≤ 50 действий в обработчике, ≤ 200 блоков на проект (текущий лимит)

## Design sequence

1. **Модель блоков.** Расширить `BlockType`, `readBlocks`, `addBlock`, `updateDrive` (переименовать в общий апдейтер или разрешить `button`/`stop`), `snapTargetInfo` (не принимать прикрепление над `button`, запрещать `if`/`start`/`button` под шапкой), `generatePybricks` (пропуск цепочек `button`, `stop` → `brake()`). Тест: старые проекты экспортируются идентично.
2. **Компилятор.** `public/controller-program.js` по [data-model.md](data-model.md): обход цепочек через ту же логику порядка, коды ошибок, `describeAction`, `commandsFor`. Тесты до интеграции.
3. **Протокол хаба v3.** `a`/`t`/`d`, лимит 1000, `SOCER3_READY`; симуляция в `tests/test_controller_hub.py`, включая таймаут во время `run_angle`.
4. **Редактор.** Категория «Пульт» в палитре (те же карточки и жесты, что «Основные»), рендер шапки с выбором кнопки/события, блок «Стоп мотора», шаблон «Держи — едет», ошибки компилятора на блоках, кнопка «Пульт» → сохранить и открыть `/controller.html?project=<id>`.
5. **Пульт.** Удалить редактор раскладки и связанный код (`draft`, `renderEditorOptions`, `bindDrag`, `bindResize`, `modulePicker`, `cloudSave`/`load` конфигурации). Добавить выбор проекта, `↻`, геймпад из 10 кнопок с `data-has-handler`, клавиатуру, `#modeBadge`, `#programErrors`, `#eventLog`. Исполнитель: `AbortController` на обработчик, последовательность действий и ожиданий, общий abort при FR-009. Сохранить без изменений BLE-подключение, старт, heartbeat, ACK, `writeBytes`, скачивание программы.
6. **Стиль.** Геймпад на `.control-button`/`.board-wrap`; лента и ошибки — карточки `notice`; мобильная раскладка: геймпад сверху, лента снизу. Проверка 360 px.
7. **Проверка.** `npm test`, `npm run build`, сценарии [quickstart.md](quickstart.md), затем аппаратная приёмка. Клиент, редактор и программа хаба публикуются одним релизом.

## Risks and boundaries

- **Старая программа хаба у учеников.** Пульт распознаёт `SOCER2_READY` и разрешает только непрерывные действия, подсказывая скачать v3.
- **Проекты только на одном устройстве.** Программа, собранная на компьютере, не появится на телефоне. Явно сказано в UI выбора проекта («проекты на этом устройстве»); синхронизация — отдельная спецификация.
- **Оценка длительности оборотов/градусов** в браузере может расходиться с хабом при нагрузке; следующий шаг цепочки может начаться раньше/позже на ~100 мс. Достаточно для учебных сценариев; точный `DONE` — будущий протокол.
- **Хабы, отличные от SPIKE/Inventor** (Technic, City) выбирались в старых настройках пульта; редактор знает только `spike`/`ev3`. В этой итерации пульт принимает проекты `spike` и любой Pybricks-хаб, если порты программы есть в READY.
- **Размер `page.tsx` (1800 строк).** Палитру категории «Пульт» и рендер новых блоков вынести в отдельные компоненты (`src/components/editor/controller-blocks.tsx`), чтобы не увеличивать монолит.

## Complexity Tracking

Ратифицированных правил нет. Новый ES-модуль компиляции и протокол v3 оправданы: первый исключает расхождение правил между редактором и пультом, второй нужен, чтобы знакомые блоки с величиной движения работали на пульте точно. Отдельный API не добавляется.

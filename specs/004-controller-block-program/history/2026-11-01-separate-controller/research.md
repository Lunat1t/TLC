# Research: Программа пульта из блоков

## R1. Где ученик собирает программу пульта

- **Decision**: В существующем редакторе `/editor`, новой категорией палитры «Пульт». Программа хранится внутри проекта (`RobotProject.workspace`, листы), как остальные блоки.
- **Rationale**: Пользователь просит «с помощью блоков» и сохранить стиль; в редакторе уже есть палитра, перетаскивание, примагничивание, листы, сохранение. Второй редактор на странице пульта дублировал бы 1800 строк логики.
- **Alternatives**: Блочный редактор внутри `controller.html` — дублирование и расхождение стиля. Отдельная страница «Программа пульта» — лишняя навигация для ученика.

## R2. Где выполняются обработчики кнопок

- **Decision**: В браузере на странице пульта. Пульт компилирует обработчики в список действий и отправляет хабу существующие строковые команды по stdin; программа хаба остаётся универсальной.
- **Rationale**: Сохраняет READY-проверку, heartbeat `k`, ACK, таймаут 600 мс и аварийный стоп; пробный режим без робота получается бесплатно; не нужно перезагружать хаб после каждой правки.
- **Alternatives**: Генерировать Pybricks-программу с обработчиками для хаба — требует передачи нажатий всё равно через BLE, перекомпиляции и повторной загрузки через Pybricks Code после каждой правки; пробный режим невозможен.

## R3. Как поддержать обороты, градусы, секунды и мощность

- **Decision**: Расширить `public/hub_program.py` до протокола v3, сохранив все команды v2: `a,<port>,<speed>,<deg>` → `run_angle(..., wait=False)`, `t,<port>,<speed>,<ms>` → `run_time(..., wait=False)`, `d,<port>,<power>` → `dc()`. Лимит скорости 1000°/с, как в редакторе. READY: `SOCER3_READY|A,B,…`. Пульт принимает и `SOCER2_READY` (только непрерывные команды и стоп).
- **Rationale**: Pybricks выполняет точное движение на хабе неблокирующе; браузерные таймеры для градусов неточны. Новая строка READY не ломает разбор портов у старого клиента.
- **Alternatives**: Эмулировать секунды таймерами браузера — дрожание BLE; запрещать величину движения в пульте — ломает знакомые блоки.

## R4. Последовательность действий внутри цепочки

- **Decision**: Действия идут сверху вниз. Непрерывный запуск и стоп — мгновенно; величина в секундах ждёт заданное время; обороты/градусы ждут расчётную длительность `deg / |speed|` + 150 мс. Повторное нажатие кнопки отменяет предыдущий запуск её цепочки. Общий стоп отменяет все цепочки.
- **Rationale**: Просто объяснить ученику и предсказуемо в ленте событий; не нужен обратный канал «движение завершено».
- **Alternatives**: Ожидать `SOCER3_DONE` от хаба — точнее, но усложняет протокол; оставлено на будущее.

## R5. Набор кнопок и клавиатура

- **Decision**: 10 кнопок: `up down left right a b x y l r`. Клавиши: стрелки → крестовина, `J K U I` → A B X Y, `Q E` → L R. События `pressed`/`released`.
- **Rationale**: Похоже на VEX IQ/геймпад и помещается на телефоне; без конфликтов с прокруткой страницы, когда фокус внутри пульта.
- **Alternatives**: Произвольные кнопки, создаваемые учеником — это возвращает «настройку пульта», которую просили убрать.

## R6. Что убрать со страницы пульта

- **Decision**: Удалить `#edit`, `aside#editor`, `#modulePicker`, `#editActions`, выбор хаба, карточки модулей, скорости портов, перетаскивание и изменение размера блоков. «↓ Программа хаба» переходит в верхнюю панель как вторичная кнопка. `/api/controller-layout` и валидаторы не удаляются в этой итерации, но пульт их больше не вызывает.
- **Rationale**: Порты, скорость и направление теперь задаются в блоках. Сохранение API избегает поломки данных профиля и позволяет откат.
- **Alternatives**: Сразу удалить API — необратимо для сохранённых профилей.

## R7. Как пульт получает проект

- **Decision**: Редактор сохраняет проект и открывает `/controller.html?project=<id>`. Пульт читает `localStorage["robot-studio-projects-v1"]` (тот же origin), валидирует и компилирует программу общим модулем `public/controller-program.js`. Без параметра — выбор из проектов на устройстве; кнопка «Обновить» перечитывает проект; событие `storage` подхватывает правки из соседней вкладки.
- **Rationale**: Проекты сейчас только локальные; один источник правды.
- **Alternatives**: Сохранять копию в профиль Supabase — нужен новый серверный контракт; вынесено за границы.

## R8. Общий код компиляции для React и статической страницы

- **Decision**: Чистый ES-модуль `public/controller-program.js` (как `controller-model.js`): `compileControllerProgram(project)` → программа или список ошибок. Редактор импортирует ту же логику через тонкую обёртку `src/lib/controller-program.ts` для проверки и подсказок; тесты запускаются `node --experimental-strip-types`.
- **Rationale**: Совпадает с текущим подходом (`controller-model.js` + `controller-layout.ts`), одна реализация правил вместо двух.
- **Alternatives**: Дублировать валидатор в TS и JS — риск расхождения.

## R9. Стиль

- **Decision**: Шапка события использует форму `start` (скругление сверху, `inset` тень снизу) в цвете категории «Пульт» `#e85d2a` / тень `#c2410c`; «Стоп мотора» — прямоугольный блок `#b1372c`/`#8f2a21` (цвет текущей кнопки «Стоп»). Экранный пульт использует существующие `.control-button`, `.board-wrap`, переменные `controller.css`.
- **Rationale**: Новые элементы различимы, но визуально из того же набора.

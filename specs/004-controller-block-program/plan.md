# Implementation Plan: Единый редактор программы и управления

**Feature context**: `004-controller-block-program` | **Git branch**: `001-instruction-library` | **Date**: 2026-11-02 | **Spec**: [spec.md](spec.md)

**Input**: объединить редактор и пульт; удалить страницу пульта; добавить область «Управление» с подвижными изменяемыми блоками видов управления; программировать реакции кнопок; использовать имеющийся модуль скорости и моторные блоки под событием запуска и кнопок.

## Summary

На `/editor` добавить визуальный блок-область «Управление», элементы Drivetrain/мотор/группа и встроенную проверку. Элементы являются источниками событий, не прямыми командами моторам. Обработчики адресуются стабильной парой `controlId/input`; моторные блоки и их модули остаются общими. Вынести BLE-сессию из DOM-зависимого `public/controller.js` в управляемый сервис, связать с жизненным циклом React, удалить статический экран и обновить ссылки. Сохранить протокол v2/v3, READY/ACK/watchdog и автономный экспорт. Ошибку обработчика показывать значком с понятной подсказкой у соответствующей экранной кнопки сразу при проверке проекта; другие исправные кнопки работают. При отпускании непрерывное движение останавливает только явно написанный обработчик либо общий стоп; первая версия поддерживает экран и клавиатуру, без физического геймпада. Прежний дизайн и задачи архивированы; реализация этой редакции ещё не выполнена.

## Technical Context

**Language/Version**: TypeScript 5.7, React 19, JavaScript ES modules; Pybricks/MicroPython для существующей программы хаба. Версии — по `package.json`, без обновления зависимостей.

**Primary Dependencies**: Next.js 15, Tailwind 3, Web Bluetooth, `public/pybricks-protocol.js`, `public/notifications.js`; собственные жесты редактора с pan/zoom. Новая библиотека перетаскивания не требуется.

**Storage**: существующий `robot-studio-projects-v1`; расширение `workspace` версией схемы управления. Прежний `tlc.controller-layout.v1` хранится отдельно. Новая схема БД не нужна; существующий layout API не меняется этим планом.

**Testing**: `npm test`, `npx tsc --noEmit`, `npm run build`, тесты чистой модели/компилятора и фальшивого транспорта, браузерная и аппаратная приёмка по [quickstart.md](quickstart.md).

**Target Platform**: HTTPS браузер с Web Bluetooth для реального управления SPIKE Prime; остальные браузеры поддерживают редактирование и пробный режим. На EV3 Bluetooth-проверка недоступна, автономный экспорт сохраняется.

**Project Type**: существующее Next.js веб-приложение с клиентским редактором и общим чистым компилятором.

**Performance Goals**: локальная обработка пробного события ≤100 мс; существующий heartbeat 150 мс и watchdog хаба 600 мс; без HTTP-запросов при нажатии кнопки.

**Constraints**: один владелец BLE-сессии; никаких команд от размещения элемента; события отделены от жестов; стабильность целей; остановка перед изменением программы; без отдельного блока скорости; сохранение прежнего автономного экспорта.

**Scale/Scope**: 32 листа, 200 программных блоков на лист; до 12 областей на проект и 12 элементов на область; до 50 скомпилированных действий на цепочку. Лимиты новых сущностей — проектное решение, остальные взяты из текущего кода.

## Phase 1 — Design

Завершено: [data-model.md](data-model.md), [contracts/controller-program.md](contracts/controller-program.md), [quickstart.md](quickstart.md).

Последовательность будущей реализации:
1. До любой новой записи проекта: построить и проверить идемпотентную миграцию в памяти до `readSheets`, сохранить и проверить backup точной исходной записи всех проектов; отказ backup/валидации/записи блокирует autosave. Между вкладками использовать Web Locks для всех новых записей с повторной проверкой исходных данных под блокировкой; при отсутствии блокировки не разрешать небезопасную параллельную запись. Старые версии, не соблюдающие блокировку, не получают гарантии изоляции: фиксировать конфликт и сохранять backup. Затем подключить layout/event targets и JSON roundtrip.
2. Чистая модель области и элементов: размеры, координаты, ID, валидатор; события без встроенных портов/скоростей.
3. UI области/drag/resize и шапок событий, используя существующие жесты и моторные компоненты. Изменение листа и клонирование согласованно обновляют ссылки.
4. Общий компилятор поддерживаемых start-цепочек и событий. Пустой input даёт только пробное событие. Неподдерживаемый start блокирует старт с диагностикой, ошибки конкретной кнопки не скрываются.
5. Выделение транспорта и исполнителя, React cleanup/Strict Mode, отмена очереди и владение портами; сохранение READY и таймингов.
6. Встроенные edit/check/trial/live, скачивание хаб-программы, явный старт ученика и безопасные стоп-переходы.
7. Удаление HTML/JS/CSS отдельного экрана, legacy redirect с project ID, обновление homepage/PWA/README и проверок маршрутов.
8. Валидация по quickstart, затем аппаратная приёмка. Не считать браузерные тесты доказательством физической работы.

`tasks.md` необходимо заново сформировать через `speckit-tasks` по этой редакции перед реализацией. Этот вызов `speckit-plan` заканчивается дизайном Phase 1 и не выполняет внедрение или публикацию.

## Решения после уточнений и анализа

- Ошибка нажатия или отпускания блокирует соответствующую экранную кнопку целиком: значок и доступная подсказка видны сразу после проверки, до старта; независимые исправные кнопки выполняются. Удалённая цель отмечается в блоке события и списке ошибок. Исправление сразу обновляет индикацию. Это уточняет границу обработчика при ошибке отпускания.
- При старом адресе с неизвестным ID или без ID показывается список доступных проектов с сообщением и явным выбором; не выбирать и не запускать проект автоматически.
- Остановка: перед `x` инвалидировать epoch, отменить очереди и heartbeat, дождаться существующего `SOCER2_STOP` в течение 1200 мс после успешной записи `x`. Повторные запросы объединяются; при timeout, сбое записи или разрыве — fault, отключение, только явное новое соединение, READY и старт. Пока ответ не получен, UI сообщает, что остановка не подтверждена. События старой сессии не принимаются после reconnect.
- SC-004 сохраняется без ослабления: ≤100 мс от пользовательского события до отображения в пробном режиме и ≤600 мс от последнего принятого хабом пакета до физической остановки. Однако код хаба проверяет `>600` с циклом `wait(10)`, а механический выбег зависит от робота. Это **неподтверждённая и потенциально недостижимая аппаратная граница**; никакая симуляция не доказывает SC-004. Записать реальное время и разрешение измерения, не отмечать критерий пройденным при превышении или отсутствии хаба; при провале уточнить требование либо проект программы хаба отдельным решением. Таймаут отсутствия обратного ACK не равен потере потока пакетов на хабе.

## Risks and boundaries

- `readBlocks`/`readSheets` пересобирают данные: новые поля необходимо сохранять на всех путях snapshot/import/clone, иначе UI потеряет ссылки.
- React Strict Mode может повторно вызвать эффекты: подключение и старт только из явного действия, cleanup идемпотентен, устаревшие async callback проверяют epoch.
- Старые глобальные раскладки не имеют project ID: только явный импорт вида, без переноса скрытой моторной логики.
- Старый UI нельзя удалить до извлечения его транспорта; удаление выполняется после интеграции и проверок.
- Жесты на телефоне и реальные BLE-тайминги требуют браузерной и аппаратной приёмки.

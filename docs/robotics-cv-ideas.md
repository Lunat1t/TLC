# Роботы и компьютерное зрение в Brick Studio

[Главная страница репозитория](../README.md)

Этот документ описывает идеи для уроков, каталог сборок и порядок разработки. Первая цель — провести занятие, на котором ученик обучает зрение на своих фотографиях, пишет правило и видит, как реальный робот выполняет его.

## Что уже есть в Asylnur

[Asylnur](https://github.com/Lunat1t/Asylnur/blob/main/README.md) — учебный робот для осмотра деревьев на макете. Телефон подключается к пульту по QR-коду. YOLO на телефоне определяет состояние дерева на макете, AprilTag помогает отличить одно дерево от другого, а пульт получает видео с рамками. Оператор вручную управляет моторами SPIKE по Bluetooth через Pybricks.

Для Brick Studio можно переиспользовать этот подход к подключению телефона и хаба. Следующий шаг — передавать результат распознавания в программу ученика как отдельное событие. Так действие сможет запускаться автоматически по его правилу. Навигация, автоматический обход и новые сборки ниже входят в план развития.

## Как ученик обучает компьютерное зрение

В проекте робота появляется вкладка **«Обучить зрение»**. По простоте процесса ориентир — [Teachable Machine](https://teachablemachine.withgoogle.com/). Из [Kaggle Learn](https://www.kaggle.com/learn/computer-vision/) берём подход к эксперименту с набором данных и отдельными примерами для проверки.

1. **Собрать примеры.** Подключить телефон по QR-коду. Создать категории «Колесо», «Кубик» и «Пусто». Снять детали на разных фонах, под разными углами и при разном освещении.
2. **Обучить модель.** Нажать «Обучить». Для первого прототипа использовать готовую модель для извлечения признаков изображения и обучать небольшой классификатор на примерах ученика. Выбор конкретной модели и места обучения остаётся открытым до проверки на устройствах пилота.
3. **Проверить на новых снимках.** Показать камере примеры, которые не участвовали в обучении. Показать ученику предсказание и оценку уверенности. Если модель ошибается, добавить примеры из проблемных условий, переобучить её и снова проверить.
4. **Запрограммировать реакцию.** Добавить блок «Когда камера распознаёт…», выбрать категорию и связать её с действием мотора. Запустить программу и проверить на реальном роботе.

В первом уроке телефон неподвижен и смотрит на отмеченную область с одним предметом. Для футболиста и манипулятора следующим шагом станет поиск положения объекта в кадре.

## Как модель связана с роботом

Телефон распознаёт предмет. В Brick Studio передаются категория и оценка уверенности. Код ученика выбирает действие, а SPIKE выполняет его через Pybricks. В отладке видны результат камеры, сработавший блок и команда мотору. Это помогает понять, где появилась ошибка.

```text
Когда камера распознаёт «Колесо» → направить деталь вправо
Когда камера распознаёт «Кубик»  → направить деталь влево
Когда камера распознаёт «Пусто»  → ждать следующую деталь
```

Подтверждаем распознавание по нескольким кадрам. Одно распознавание запускает одно движение, а повтор разрешается после освобождения зоны. Если уверенность низкая, механизм ждёт. Для подвижных проектов закладываем общий стоп и остановку при потере свежих данных.

**Следующий уровень — обучение на действиях ученика.** Ученик вручную ведёт машинку по учебной трассе. Studio записывает кадры и команды «прямо», «влево», «вправо», «стоп». Модель учится выбирать одну из этих команд, а программа исполняет её в заданных пределах скорости и останавливает робота при потере сигнала. На одной сборке можно сравнить правила, написанные руками, и поведение, обученное на демонстрациях.

## Каталог роботов

Для механизмов первые уроки можно проводить с телефоном на подставке. Для мобильных проектов камера над полем может одновременно видеть робота, цель и границы площадки. В зависимости от урока используем классификацию, поиск объекта в кадре, отслеживание движения или метки AprilTag.

## Порядок разработки и пилот

1. **Asylnur** показывает распознавание и ручное управление на реальном роботе.
2. **Сортировщик LEGO-деталей** — первый урок с автоматической реакцией. Для сборки хватает SPIKE Prime, неподвижного телефона, одного мотора, заслонки и двух лотков. В интерфейсе нужны три класса, кнопка «Обучить», проверка на новых примерах и один блок реакции.
3. **Курьер по станциям** вводит маршруты и AprilTag. Ученик задаёт, что делать на каждой метке.
4. **Футболист SPIKE** вводит координаты мяча в кадре, подруливание и разные стратегии на общей сборке.

На первом уроке ученик снимает примеры, исправляет хотя бы одну ошибку модели и показывает сортировку новых деталей на реальном роботе. Он сдаёт проект, а преподаватель отмечает освоенный навык. Критерий готовности для внешнего пилота — другой преподаватель может повторить урок по инструкции без помощи автора.

После этого проверяем платный пилот с кружками. Дальнейшее развитие включает конструктор уроков и задания для групп, портфолио и родительский прогресс, отчёты для менеджера, облачное хранение и управление местами. Интерактивные уроки для самоучек, персонажи, острова, мини-игры, сезонные награды и инструменты для филиалов остаются направлениями развития.

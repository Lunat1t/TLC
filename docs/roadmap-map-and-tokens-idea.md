# Идея по роадмапу — карта проектов, миссии и токены навыков

Статус — идея для будущей разработки.

Зафиксировано 19 ноября 2026 года по обсуждению с владельцем TLC. Документ описывает желаемое поведение и вопросы для дальнейшей проработки. Реализацию вести отдельной задачей после подготовки контента и согласования открытых решений.

## Цель

Дать ученику понятный выбор следующего проекта, видимую награду за его сложность и общий путь развития. Родитель видит выполненные работы и развитие механики, логики и творчества. Преподаватель проверяет результат и подтверждает награды в ходе обычного занятия.

Сейчас ученики выбирают интересных роботов из каталога. Карта должна сохранить выбор, связать проекты с учебными целями и показать дальнейшее развитие.

## Согласованные правила

- Три навыка — механика, логика и творчество.
- Токены навыков заменяют XP в будущей системе прогресса.
- У каждой модели собственный заранее настроенный дроп токенов по навыкам.
- Награда зависит от сложности конкретной сборки и программы. Количество токенов у разных роботов различается.
- Ученик видит дроп до выбора проекта на карте.
- Один робот может приносить токены нескольких навыков.
- Сборка даёт предусмотренные для неё токены механики. Выполненная программа даёт предусмотренные для неё токены логики.
- Творчество развивается через самостоятельные миссии и дополнительные достижения, которые подтверждает преподаватель.
- Повторная сборка уже пройденного робота как очередное прохождение запрещена. Повторное начисление за ту же работу исключается.
- Знакомую конструкцию разрешено использовать как основу нового решения в творческой миссии.
- Ранг и ступень карты объединяются в один путь развития.
- Для Junior+ требуется суммарно 5 токенов любых навыков. Например, 3 механики и 2 логики.
- На шкале продвижения видны разные виды заработанных токенов.
- Родитель видит статистику ребёнка по трём навыкам и результаты работ.

## Структура карты

Последнее предложенное устройство карты — две ветки внутри общей карты ранга.

| Ветка | Содержание |
| --- | --- |
| Роботы | Готовые проекты с инструкцией, заданиями по сборке и программированию |
| Миссии | Задачи с целью и условиями, для которых ученик придумывает конструкцию и программу |

Каждый робот имеет одну карточку. Механика, логика и творчество являются видами навыков и наград. Робот с дропом механики и логики размещается в карте один раз.

Рекомендуется позволить ученику посмотреть проекты, развивающие нужный навык, через фильтр или выделение карточек. Конкретное оформление двух веток ещё предстоит утвердить.

## Ранги и открытие проектов

| Ранг | Ступень карты |
| --- | --- |
| Junior | 1 |
| Junior+ | 2 |
| Midle | 3 |
| Midle+ | 4 |
| Senior | 5 |
| Senior+ | 6 |
| King | 7 |

Названия сохранены в написании владельца проекта.

Получение ранга открывает соответствующую ступень карты. В интерфейсе ступень можно называть самим рангом, например «Проекты Junior+», чтобы ученик видел одну систему продвижения.

Порог Junior+ — 5 токенов любых навыков. Пороги остальных рангов определить после сортировки роботов и оценки доступного дропа. Ранее обсуждавшиеся 10 уровней на ранг и формула XP относятся к прежней системе.

Предложение для реализации — считать пороги по общему числу заработанных токенов за всё время и сохранять накопленные токены после повышения. Остаток старых проектов оставить доступным. Эти правила требуют окончательного подтверждения.

При свободном сочетании токенов у ученика может преобладать механика. Это ожидаемое поведение при текущем правиле повышения. Минимальные квоты каждого навыка пока не согласованы.

Ранее рассматривалось обязательное прохождение всех роботов уровня перед переходом. После перехода к модели ранга за суммарные токены это условие требует отдельного решения. В первой ступени может быть больше доступных наград, чем нужно для Junior+.

## Дроп и подтверждение наград

Преподаватель или редактор учебного контента задаёт для проекта отдельные задания, критерии проверки и количество токенов каждого навыка.

| Часть проекта | Основание для награды |
| --- | --- |
| Сборка | Работоспособная конструкция и выполненное задание по механике |
| Программа | Программа выполняет условия задания |
| Творческое задание | Собственное решение или изменение соответствует объявленным условиям |

Токены логики получают на том же собранном роботе, для которого пишут программу. Общая сложность проекта складывается из разных частей. Простая сборка может сопровождаться сложной логикой и большим дропом логики.

Пример карточки из обсуждения — «Прыгун», механика ×2, логика ×1. После принятой сборки начисляются 2 токена механики, после принятой программы — 1 токен логики.

Полный дроп показывается заранее. Если ученик выполнил часть проекта, интерфейс показывает уже полученные и оставшиеся награды. Повторная проверка или повторная отправка запроса должна возвращать прежний результат выдачи.

Дополнительные токены творчества преподаватель может выдать за собственное улучшение. Критерии, лимиты и связь таких наград с конкретным проектом ещё нужно определить.

Перед переносом в каталог проверить это прочтение, точные названия и соответствие каждой модели существующей инструкции. Список и награды остаются черновиком для подготовки контента.

## Творческие миссии

У миссии есть сюжет, практическая цель, проверяемые условия, доступные ограничения и собственный объявленный дроп.

Пример — «Спаси LEGO-фигурки». Фигурки находятся в яме или опасной зоне. Ученик должен создать робота, который достанет их и перевезёт в безопасное место.

Можно построить собственного робота или переработать знакомую конструкцию. Возможные решения — кран, подъёмник, машина с захватом. Преподаватель проверяет выполнение условий миссии.

За миссию могут начисляться творчество, механика и логика в заданном соотношении. Конкретные количества определить при создании миссии.

За использование знакомой модели в миссии начисляется награда самой миссии. Первоначальные награды за пройденную модель остаются однократными.

Предложение — некоторые миссии открывать после подходящего практического опыта. Например, спасение становится доступно после проекта с захватом или подъёмом. Зависимости и возможность альтернативных путей нужно утвердить.

## Повторение учебных тем

Одну тему повторяют на разных роботах и в миссиях. Например, принцип шестерён встречается на мельнице, карусели и подъёмнике, а цикл — в программах разных моделей.

Предложенный порядок для темы — знакомство с объяснением, новый проект с меньшим количеством подсказок, затем самостоятельное применение в новой задаче. Между такими проектами располагаются другие темы.

Интервалы через 1, 3 или 6 занятий обсуждались как пример для пилота. Конкретное расписание для LEGO требует проверки на учениках. Следует учитывать даты занятий и результат самостоятельной проверки.

Исследования, рассмотренные при обсуждении идеи, поддерживают распределённую практику, воспроизведение знаний и постепенное уменьшение подсказок. Указанные работы не проверяют именно эту карту TLC или правило обязательного сбора всех моделей.

- Cepeda et al., 2008, Spacing Effects in Learning — [страница автора](https://www.yorku.ca/ncepeda/publications/CVRWP2008.html).
- Rohrer et al., 2020, A Randomized Controlled Trial of Interleaved Mathematics Practice — [запись исследования](https://eric.ed.gov/?id=EJ1237752).
- Atkinson, Renkl & Merrill, 2003, Transitioning from Studying Examples to Solving Problems — [запись исследования](https://eric.ed.gov/?id=EJ678596).
- Karpicke & Blunt, 2011, Retrieval Practice Produces More Learning — [запись исследования](https://pubmed.ncbi.nlm.nih.gov/21252317/).

## Профиль ученика и просмотр родителем

В профиле ученика показываются общий ранг, продвижение к следующему рангу, количество токенов каждого навыка и выполненные проекты.

Шкала ранга содержит различимые цветные части и символы навыков. Например, 3 токена механики и 2 логики образуют 5 токенов для Junior+. Подписи и числа дополняют цвета.

Предложение для карточки проекта — изображение, название, доступность, дроп по навыкам, краткие задания и полученные награды. При открытии видны подробные критерии.

Родитель видит те же подтверждённые результаты ребёнка, распределение токенов, выполненные модели и миссии. Предлагается добавить дату и короткое пояснение преподавателя о том, что ребёнок сделал самостоятельно.

Обсуждавшиеся ранее три шкалы навыков можно выразить количеством токенов каждого вида. Отдельные уровни каждого навыка и их пороги пока не определены.

## Токены и номиналы

Токены навыков служат для прогресса и ранга. В профиле также обсуждалась отдельная валюта «номиналы» для будущих покупок. Правила её получения и магазина нужно разработать отдельно. Автоматический обмен токенов навыков на покупки не согласован.

## Вопросы перед разработкой

1. Утвердить отображение двух веток «Роботы» и «Миссии».
2. Завершить сортировку моделей и назначить критерии и дроп каждой.
3. Определить пороги Midle, Midle+, Senior, Senior+ и King.
4. Подтвердить накопительные пороги, доступность старых проектов и правило полного прохождения ступени.
5. Определить порядок и зависимости проектов внутри ранга.
6. Определить награды и критерии самостоятельных миссий и дополнительных наград творчества.
7. Уточнить, какие части проекта обязательны для отметки «Проект завершён».
8. Определить перенос существующего XP и ранее подтверждённых работ в токены.
9. Определить поведение при изменении дропа уже опубликованного задания и исправлении ошибочной награды.
10. Проверить темп повышения ранга и запоминание тем на пилотной группе.

## Предлагаемый порядок будущей разработки

1. Подготовить небольшой набор проектов Junior и Junior+ с заданиями и дропом.
2. Спроектировать хранение карты, зависимостей, подтверждений и однократных наград.
3. Добавить преподавателю настройку заданий и выдачу наград через зачёт работы.
4. Добавить ученику карту проектов, ранги и шкалу токенов.
5. Добавить родителю просмотр подтверждённого прогресса.
6. Добавить творческие миссии и возвращение к темам через новые проекты.
7. По пилоту скорректировать дроп, пороги и последовательность уроков.

При реализации предусмотреть серверную проверку выдачи наград, защиту от повторного начисления при повторных запросах и одновременных проверках, доступ родителя только к связанному ученику и сохранение истории выданных наград.

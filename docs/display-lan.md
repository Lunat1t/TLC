# Камера телефона в блоке «Дисплей»

## Подключение на публичном сайте

1. Подключите устройство с редактором и телефон к одной сети Wi-Fi.
2. На [Brick Studio](https://techlabcode.vercel.app/) войдите в аккаунт, добавьте «Дисплей» в область «Управление» и нажмите «Подключить телефон».
3. Отсканируйте QR штатной камерой телефона, откройте ссылку и нажмите «Включить камеру». Вход на телефоне и установка сертификата для публичного сайта не требуются.

Для открытия публичного сайта и первоначального обмена параметрами соединения нужен интернет. Видео передаётся напрямую между устройствами без звука. После обмена SDP ошибка облачного опроса не закрывает текущий поток: опрос повторяется для продления аренды, а состояние медиа проверяется отдельно. Если аренда истекла, работающий поток сохраняется, но для нового соединения нужен новый QR. Это не делает публичный сайт полностью офлайн. Целевое качество — 720p и до 32 кадров/с, фактическое зависит от камеры, браузера и сети. Гостевая сеть с изоляцией клиентов может блокировать прямую передачу.

## Поворот видео

Видео на дисплее поворачивается вслед за телефоном, даже если поворот экрана на телефоне заблокирован. iPhone при нажатии «Включить камеру» дополнительно спросит доступ к движению и ориентации — разрешите его. Без разрешения или без датчика видео поворачивается только вместе с экраном. Если телефон лежит почти плашмя, сохраняется последнее положение. После обновления сайта перезагрузите и редактор, и страницу камеры (новый QR).

## Локальный запуск

На компьютере с OpenSSL выполните:

```sh
npm run dev:lan
```

Откройте адрес HTTPS, который напечатает скрипт. Если у компьютера несколько сетевых интерфейсов, задайте IPv4 Wi-Fi вручную через `npm run dev:lan -- --host <IPv4 компьютера>`. Порт по умолчанию — 3443. На гостевой сети с изоляцией клиентов телефон может не видеть компьютер.

### Первый запуск на устройствах

Камера в мобильном браузере требует доверенного HTTPS. Скрипт создаёт собственный локальный удостоверяющий центр и печатает пути к открытым файлам для установки. [Доступ браузера к камере](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia).

- **iPhone или iPad.** Перенесите `BrickStudio-LAN.mobileconfig` на устройство, установите профиль в «Настройки → Основные → VPN и управление устройством». Затем включите доверие к Brick Studio Local Display в «Основные → Об этом устройстве → Доверие сертификатам». [Инструкция Apple](https://support.apple.com/ru-ru/102390).
- **Android.** Перенесите `rootCA.cer` и установите его как сертификат центра сертификации в настройках безопасности и хранилища учётных данных. Названия пунктов зависят от устройства.
- **Компьютер с редактором.** Доверьте `rootCA.cer` в хранилище корневых сертификатов, которым пользуется браузер. Переносите на устройства только открытый сертификат или профиль. Закрытый ключ остаётся в частной папке компьютера.

### Подключение

HTTPS-адрес использует отдельное хранилище браузера. Войдите в Brick Studio на этом адресе. Чтобы продолжить уже начатый проект с прежнего адреса, выберите проект на рабочем столе, нажмите «Скачать файл», затем на HTTPS-адресе выберите «Открыть файл проекта».

В редакторе добавьте «Дисплей», откройте его QR и отсканируйте штатной камерой телефона. Перейдите по ссылке и разрешите доступ к камере. Видео идёт напрямую между браузерами через WebRTC, звука нет. Целевые настройки — 720p и до 32 кадров в секунду. Реальный режим зависит от камеры, браузера и сети.

Сигнальные сессии живут в памяти локального сервера. Используйте HTTPS-адрес из этого запуска и в редакторе, и на телефоне. Сеанс завершается кнопкой остановки, закрытием блока или перезапуском сервера.


## Диагностика задержки

На обоих устройствах при активном соединении есть небольшой значок графика «Диагностика видео». Он открывает окно поверх страницы, не закрывая трансляцию. Данные обновляются раз в секунду: выбранный UDP/TCP и типы ICE-кандидатов, codec, фактические FPS/поток, RTT, кодирование/декодирование на кадр, средний jitter buffer за последний интервал, потери и зависания. На телефоне показаны настройки захвата и ограничение кодировщика. IP-адреса, SDP, QR-токен и идентификаторы устройств не сохраняются и не отправляются. Можно скачать локальный JSON замера.

«Прямой» означает отсутствие relay в выбранной паре, а не доказательство маршрута внутри конкретной Wi-Fi сети. RTT — время туда-обратно, а не задержка видео. Оценка «захват → показ» доступна только когда браузер сообщает captureTime; на телефоне она относится к локальному предпросмотру. «—» означает отсутствие данных. Без requestVideoFrameCallback время последнего показанного кадра тоже недоступно.

Для живого видео запрошены contentHint=motion и maintain-framerate (при нагрузке разрешается снижение разрешения); ограничение камеры остаётся до 1280×720/32fps. На приёмнике, если API поддерживается, запрошен jitterBufferTarget=0. Это подсказки: браузер выбирает фактический буфер, а меньший буфер может увеличить пропуски при плохой сети. Ускорение без реального сравнения не подтверждено.

### Короткий проход с телефоном

1. Откройте проверяемую HTTPS-версию на компьютере и соедините телефон по прежнему QR. После появления видео подождите 10 секунд и скачайте замер на обоих устройствах.
2. Для видимой задержки наведите телефон на секундомер с миллисекундами на экране компьютера: одновременно должны быть видны сам секундомер и его изображение в видео. Сфотографируйте оба показания и сравните их; повторите несколько раз. Это отдельный замер, не RTT.
3. Наблюдайте минуту: FPS, кодирование, буфер, потери и возраст последнего кадра. Скачайте JSON при заметном отставании/зависании.
4. Сохранив общую Wi-Fi сеть, временно отключите у роутера только интернет (если это ваша сеть и не мешает другим). Текущий прямой поток не должен закрыться из-за ошибки облака. Затем верните интернет. Открытие сайта и нового QR без интернета этим не проверяется.
5. Отдельно кратко отключите Wi-Fi телефона и верните: короткий разрыв может восстановить ICE сам браузер; если соединение завершилось, откройте новый QR. Полного автоматического переподключения/ICE restart эта версия не добавляет.

Локальная проверяемая версия требует доверенного HTTPS по инструкции выше; обычный HTTP по IP не подходит для камеры. Продакшен-сервер Next.js использует облачную сигнализацию независимо от локального IP; локальная сигнализация в памяти применяется только в dev:lan.

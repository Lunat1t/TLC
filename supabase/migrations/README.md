# TLC instruction library migrations

Use a separate, non-production Supabase project for first application and checks. Apply `supabase/schema.sql` first if the project does not already have the TLC `profiles` table and Auth trigger. On an existing project, inspect its `profiles` policies and table definitions before applying any feature migration.

For a fresh test project, apply `supabase/schema.sql`, then the available SQL files in this order: `20261030_instruction_admins.sql`, `20261030_instruction_catalog.sql`, `20261030_instruction_storage.sql`, `20261104_instruction_drive_source.sql`, `20261105_security_cleanup.sql`, `20261105_instruction_admin_acl.sql`, and `20261105_instruction_drive_revisions.sql`. The profile policy grants authenticated users access only to their own profile; the admin migration adds trusted admin reads before any roster is exposed. The cleanup migrations remove the duplicate self-read policy, prevent direct Data API execution of the profile trigger function, and restrict the admin-check function to authenticated/service roles. Drive revisions default to unverified and may not be used for launches until the server confirms retention.

The `instruction-assets` bucket is private and accepts images only. PDFs stay in Google Drive; they are represented by Drive metadata and are never copied to this bucket. The current migration set creates the profile/admin/catalog schema, but does **not** yet create student sessions, selections, launches, or progress. Do not treat student launch flows or protected PDF delivery as ready until their migrations and checks are implemented. Apply each file once and record the version. Use a dedicated non-production project with test identities for subsequent end-to-end validation; do not apply this sequence directly to production before successful test-project checks.

Never place a service-role key in browser code. The web app uses the existing publishable key and verified user session. Trusted `security definer` functions must check `auth.uid()` and the active Auth session before reading or writing protected rows. See `specs/001-instruction-library/quickstart.md` for the validation sequence.
